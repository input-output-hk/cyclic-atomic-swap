### Cooperation and documentation

1. We conceived a methodology to coordinate the theoretical description of the problem (the CANS protocol in our case), 
   its formal method description and challenge, the architectural documentation and the code implementation.
2. From the formal method description of the problem yields a rigorous theoretical description of the problem 
   and the proposed solution in algorithmic terms.
3. The architectural documentation maps between the theoretical description and the code implementation. 
   In our work-stream, CANS is theorized as a distributed finite state machine.
   The architectural model provides C4/UML schemas where every state is graphically represented, 
  and its graphic representation maps to the data structures and code activating the state. 
  This representation makes it easy to understand and move between the theoretical description of the CANS protocol, 
  the code and formal methods challenges.
4. A non-technical presentation of the work-stream's results. 
   The slide deck introduces the CANS solution. 
   After reading the slides, anyone interested will be competent to understand section 3. 
   and adapt the code according to their specific needs.
